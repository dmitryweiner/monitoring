## Вход в Tailscale заблокирован fake-ip — 15 сентября, 07:10 UTC

Владелец запустил net-inspect.sh, затем tailscale up: страница входа не открылась,
принудительный tailscale login висит без ошибок. Причина установлена.

- В 06:00:34 mihomo перезапустился и зарегистрировал свой DNS в systemd-resolved
  как Link 6 (Meta) с сервером 198.18.0.2. Четырнадцатого сентября этого не было:
  DNS обслуживал только wlan0 через роутер 192.168.100.1. Сейчас DNS-область
  есть у обоих линков, и на имена Tailscale отвечает mihomo.
- Имена получают fake-ip: controlplane.tailscale.com → 198.18.0.91,
  login.tailscale.com → 198.18.0.93, derp1.tailscale.com → 198.18.0.92.
- Дальше два механизма бьют друг друга. Пакет без метки идёт в TUN, где mihomo
  разворачивает fake-ip обратно в домен, — поэтому tailscale netcheck отработал
  и показал честные задержки DERP. Пакет tailscaled несёт метку 0x80000,
  правило 5210 уводит его мимо TUN на роутер 192.168.100.1, а тот не знает,
  что делать с 198.18.0.91. Пакет исчезает молча, ошибки нет, вход висит.
- Проверено прямо: ip route get 198.18.0.91 mark 0x80000 даёт
  via 192.168.100.1 dev wlan0, без метки — via 198.18.0.2 dev Meta.
- Это ровно тот риск, который был записан 14 сентября как предположение.
  Обход TUN по метке — не только средство защиты, но и то, что ломает вход,
  когда DNS отдаёт подделку.
- Написан deploy/mihomo-tailscale-dns.py: вносит +.tailscale.com и +.tailscale.io
  в fake-ip-filter, делает резервную копию, проверяет mihomo -t до перезапуска,
  восстанавливает копию при отказе конфигурации или службы. Фильтр по доменам,
  а не по адресам, переживает смену адресов DERP. На момент записи не запускался.
- Прочее из инвентаризации: netcheck UDP true, внешний адрес получен,
  ближайший DERP Nuremberg 129.9 мс, CaptivePortal false. iptables установлен,
  но все цепочки пусты с политикой ACCEPT; nft отсутствует. sshd слушает 22
  на всех адресах, PermitRootLogin yes и PasswordAuthentication yes —
  при выходе в tailnet это стоит пересмотреть отдельно.
- Испытательные режимы net-failover-test.sh не запускались: без входа
  в Tailscale проверять нечего.
